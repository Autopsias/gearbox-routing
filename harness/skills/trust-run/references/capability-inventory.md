**Provider packs.** The registry names only generic providers. A user's own search, read and write tools join the chain through a **provider pack**: a `provider_pack_*.py` file next to `adapter_registry.py`, or any path listed in `OTL_PROVIDER_PACKS`. A pack declares data only and inserts its providers ahead of the generic ones for the operations it names; a pack that fails to load is skipped whole and recorded, and the run continues on the generic chain. `python3 adapter_registry.py --resolve [--tools a,b]` prints each operation's bound provider, its degraded flag, and the packs loaded and failed. A provider supplied by a pack is a preferred provider, so binding to it is not a degradation.
